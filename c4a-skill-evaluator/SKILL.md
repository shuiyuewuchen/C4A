# C4 Skill Submission Evaluator（C4 提交自动评审器）

## 这个技能做什么

把"老师/助教手动翻群文件、挨个检查作业齐不齐、写评语"这件事自动化。

输入一个本地文件夹路径 → 输出一份带排名、打分、改进建议的评审报告。

```
WeChat 群文件下载目录
        │
        ▼
  ┌─────────────────────┐
  │ 1. 扫描 & 识别作者   │  ← 按文件名 `_C4_` 前缀提取
  ├─────────────────────┤
  │ 2. 完整性检查        │  ← 5 个必须文件 ✅/⚠️/❌
  ├─────────────────────┤
  │ 3. 四维质量评审      │  ← 可复用/可执行/可验证/IO明确
  ├─────────────────────┤
  │ 4. 报告生成          │  ← Markdown + Excel + JSON
  └─────────────────────┘
```

## 快速使用

### 命令行（纯规则，零依赖 LLM）

```bash
python3 scripts/c4_evaluator.py /path/to/c4_submissions --out ./output
```

产物：
- `output/评审报告.md` — 给人看的完整报告
- `output/评审详表.xlsx` — 给老师/教务汇总用
- `output/eval_summary.json` — 机器可读

### 作为 Agent 技能使用（推荐：规则 + LLM 混合）

当本 SKILL.md 被 Agent 加载时，按以下流程执行：

1. **先跑命令行脚本**，拿到确定性的初评结果（Markdown 报告）。
2. **再做 LLM 深审**：对每个作者的文本文件，Agent 自己读一遍，在脚本输出的"质量评审"表格基础上：
   - 修正规则误判（例如规则把 `example.com` 当成"示例"信号）
   - 补充规则看不到的语义证据（例如"安装步骤写得很敷衍，只说了'pip install'没说装啥"）
   - 把改进建议写得更具体、更个性化
3. **合并输出**：在最终报告里，用 "🤖 规则初评" 和 "🧠 AI 深审" 两栏区分，让老师知道哪些是机器判的、哪些是 AI 判的。

## 依赖

- Python 3.9+（必需）
- `openpyxl`（生成 Excel 详表必需；v1.2 已安装并验证产出）
  - 安装：`pip install openpyxl`
  - 缺失行为：不中断，Markdown 报告正文给出「⚠️ 本次未生成 Excel 详表」提示，`eval_summary.json` 的 `excel_written=false`
- 无网络、无 API key 也能跑

## 评分公式（v1.1）

```
完整率 = Σ(每个交付物权重) / 5    # 0-1 连续值
  每个交付物权重 = 匹配档位 × 内容充实度
    匹配档位：强匹配 1.0 / 文件名命中 0.5 / 弱扩展名 0.3
    内容充实度：文本 >500字=1.0，150-500字=0.8，<150字=0.5；代码同理；媒体按文件大小
综合分 = 完整率 × 0.4 + 质量均分 × 0.6
质量均分 = (✅=1.0, ⚠️=0.5, ❌=0.0 之和) / 4
```

v1.1 修复：空文件/两行文件不再拿满分——交了 5 个 stub 和交了 5 个完整文件不再同分。

## 评审维度速查

### 完整性（5 个必须文件）

| 交付物 | 强信号（✅） | 弱信号（⚠️） |
|--------|-------------|-------------|
| Skill 说明 | 文件名含 `skill说明`/`skill_doc`，且内容含"输入/输出/使用场景" | 仅文件名命中 |
| 可执行内容 | `.skill` / `.py` / 含代码块的 .md，有 YAML frontmatter | 仅内容里有 def/import |
| Demo | `.mp4/.mov/.png/.jpg/.gif` 文件名含 demo/演示 | `demo说明.md` 类文本 |
| 教学说明 | 文件名含 教学/tutorial/quickstart，且内容含 上手/步骤/安装 | 仅文件名命中 |
| AI 日志 | 文件名含 AI日志/AI_log，且内容含 prompt/迭代/具体工具名 | 仅文件名命中 |

### 质量（4 个维度，各 ✅/⚠️/❌）

| 维度 | 通过标准（≥2 项） |
|------|------------------|
| 可复用 | 有安装说明 / 无硬编码绝对路径 / 列了环境依赖 |
| 可执行 | 含可运行代码或 workflow / SKILL.md 有 YAML frontmatter / 无明显语法错误 |
| 可验证 | 有测试或示例 / 有预期输出定义 / 有真实 demo 产物 |
| IO 明确 | 有"输入X，输出Y"一句话 / 写了输入类型 / 写了输出类型 |

（综合分公式见上方"依赖"段下的 v1.1 说明。）

## 边界情况处理

| 情况 | 处理 |
|------|------|
| 空文件夹 | 报告"未找到 C4 相关文件"，提示检查路径和命名规范 |
| 文件名不规范 | 回退到一级子目录名作为作者；仍识别不到标 Unknown |
| 非 C4 文件混入 | 自动过滤（文件名不含 `_C4_` 且子目录不是作者目录） |
| 二进制文件（mp4/png） | 只读文件名，不读内容 |
| 大文件（>200KB 文本） | 只读前 200KB |
| 同作者多版本 `_v2`/`_v3` | 当前 v1：全部保留；后续版本可加 `--latest-only` |

## 扩展点（给二次开发者）

- 想改评分权重：改 `QUALITY_CRITERIA[*]["weight"]`
- 想加新的完整性检查项：在 `REQUIRED_DELIVERABLES` 加 key
- 想接 LLM 深审：在 `evaluate_quality()` 后加一个 `llm_review()` 钩子
- 想接 WeChat 自动同步：写个 `wechat_sync.py` 把群文件拉到本地，再喂给本脚本
